# ADR-0001：系统提示词五层分层（L1–L5）

- 状态：已接受
- 日期：2026-10-13
- 关联：儿童陪伴模式 spec（issue #1）、工单 #3
- 术语：见根目录 `GLOSSARY.md`

## 背景

系统提示词原先由 `agent-base-prompt.txt`（Jinja2 模板）整体渲染，再由
`Dialogue.get_llm_dialogue_with_memory` 在每轮注入记忆。各内容块的排列
顺序由模板书写顺序隐式决定，没有显式契约：后续要挂儿童档案、长期记忆、
滚动摘要、输出安全门时，缺少可定位、可测试的注入点。

儿童陪伴模式（参考小布 accompany 的 ADR-0002）要求提示词按**变更频率
升序**分层，排序目标是**前缀缓存命中率最大化**：稳定内容放前面，每轮
变化的内容放后面，稳定期只有尾部新增内容全价。

## 决策

system prompt 重排为五层固定顺序结构，每层以显式边界标记包裹：

| 层 | 边界标记 | 目标内容 | 变更频率 | 现状等价物（本票填充） |
|---|---|---|---|---|
| L1 | `<layer-1-persona>` | 静态人设/安全 | 连接期内不变 | 模板静态段 + `<identity>` 角色设定 + `<safety_compliance>` |
| L2 | `<layer-2-profile>` | 档案/年龄档位 | 家长修改时变 | `<context>` 设备上下文（时间/日期/位置/天气/动态上下文） |
| L3 | `<layer-3-memory>` | 长期记忆 | 记忆抽取时变 | `<memory>` 标签（每轮 `memory_str` 正则替换，机制不变） |
| L4 | `<layer-4-summary>` | 滚动摘要 | 窗口压缩时变 | 暂空（现状无独立摘要来源，摘要混在 memory_str 中） |
| L5 | （无标记） | 对话窗口 | 每轮变 | system 消息之后的对话消息列表（`Dialogue` 历史） |

要点：

1. **顺序固定为 L1→L5，只追加不重排。** 排序按变更频率升序，服务前缀
   缓存：前缀越稳定，命中越长。L5 是消息数组（system 之后），天然是该
   连接内变更最频繁的尾部。
2. **边界标记是注入契约。** 标记写在 `agent-base-prompt.txt` 渲染结果
   中，供后续票与测试定位（先例：`tests/core/test_prompt_layers.py`
   以 fake LLM 断言五层顺序）。后续票向 L2/L4 挂内容时，沿用 L3 的
   注入方式（对边界内标签做替换），不改动 L1。
3. **本票行为等价。** 各层内容为现状等价物原样填充，语义零改动；对话
   行为与重排前一致（现有测试全绿）。

## 后果

- 正面：提示词结构有了可断言的契约；儿童档案（L2）、长期记忆条目
  （L3）、滚动摘要（L4）、安全门与窗口压缩（L5 侧）都有了明确挂点。
- 负面/现状局限：
  - `<context>` 内 `{{current_time}}` 每轮替换，导致 L2 之后的前缀缓存
    实际失效——这是重排前就存在的行为，本票不改；是否把时间挪出前缀
    留待后续票决策。
  - 自定义 `prompt_template` 的部署不含边界标记，分层契约只对默认模板
    生效。
- 否决项：
  - **不做层配置化/层开关**——YAGNI，骨架先行，后续票按需挂内容。
  - **不按语义分组排序**（如「工具说明放最后」）——语义分组不保证变更
    频率单调，前缀缓存收益无法推理。

## 复检指引

变更 `agent-base-prompt.txt` 或 `core/utils/dialogue.py` 的注入逻辑时，
必须保持五层顺序与边界标记；`make test-python` 中
`tests/core/test_prompt_layers.py` 为守护测试。
